# Contributing Guidelines & Licensing Policy

Thank you for your interest in contributing to this project. To preserve perpetual software freedom and legal clarity for all users and contributors, all contributions are governed by the rules below.

## 1. Inbound = Outbound Licensing
This project follows a strict **Inbound = Outbound** licensing model:
- By submitting a pull request, patch, issue snippet, or any other contribution to this repository, you certify that you have the legal right to submit the work and that you license your contribution under the **GNU Affero General Public License v3.0 or later (`AGPL-3.0-or-later`)**.
- No separate Contributor License Agreement (CLA) or copyright assignment is required. You retain the copyright to your original contributions while granting the project and all downstream recipients the rights defined in `AGPL-3.0-or-later`.

## 2. Clean Codebase & License Identification
- Do **not** add per-file `SPDX-License-Identifier` headers or full license blocks to individual source files unless explicitly requested by the maintainers. License coverage for the repository is declared centrally via the root [`LICENSE`](LICENSE) file.
- If you incorporate third-party code compatible with `AGPL-3.0-or-later` (e.g., `GPL-3.0-or-later`, `LGPL-3.0-or-later`, `Apache-2.0`, `MIT`, `BSD-3-Clause`), you must preserve its original copyright notices and document the third-party component in [`NOTICE.md`](NOTICE.md).

## 3. Requirements for Modified Files and Interactive Interfaces
If you redistribute or deploy modified versions of this software (including network/SaaS deployments under Section 13 of the AGPLv3):
1. **Prominent Modification Notices**: Every modified file must carry a prominent notice stating that you changed the file and the date of any change (Section 5a).
2. **Interactive Legal Notices**: Any graphical, web, or command-line interface that displays legal notices in the original version must continue to display appropriate legal notices (copyright, warranty disclaimer, license terms, and instructions to view the Corresponding Source) in modified versions (Section 5d).
3. **Corresponding Source**: You must make the complete Corresponding Source (including build scripts, interface definitions, and installation information where applicable) available at no charge to all recipients and network users (Sections 1, 6, and 13).

Significant contributors are listed in the [`AUTHORS`](AUTHORS) file alongside the repository's version control history.
